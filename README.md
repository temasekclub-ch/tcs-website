# Temasek Club Switzerland website

A small, fast website (plain HTML, CSS and JavaScript, no build step) whose content is edited in a **Google Sheet** by non-technical volunteers.

| Who | Read |
|---|---|
| Editors (update the content) | [`docs/EDITOR-GUIDE.md`](docs/EDITOR-GUIDE.md) |
| Whoever sets it up or hands it over | [`docs/SETUP.md`](docs/SETUP.md) |
| Developers | this file |

## How it works

```
Google Sheet  <-- editors change rows
     |
Apps Script (apps-script/Code.gs, deployed as a web app)
     |  GET  ?action=content   -> the sheet as JSON (read live on every request)
     |  POST (contact form)    -> email to temasekclub.ch@gmail.com + a row in the Messages tab
     v
GitHub Pages (this repository, static files)
     content-loader.js  fetches the JSON on every page load
     content-render.js  builds the cards, lists and texts from it
```

1. `config.js` holds the Apps Script address (`api`). With it empty, every page simply shows the content written in its HTML.
2. `content-loader.js` fetches `?action=content`. The last good answer is kept in `localStorage`, so repeat visits show content at once and update a moment later if the sheet changed. If the sheet cannot be reached the saved copy is used, and if there is none the content in the HTML is used.
3. While the first answer is awaited, areas marked `data-tcs` are hidden (class `tcs-wait` on `<html>`, removed after rendering or after a time limit), so the built-in text never flashes and then changes.
4. `content-render.js` has one renderer per area. Each looks for its own element and does nothing if the page does not have it. Text is always inserted with `textContent` (never as HTML); links are checked (`http(s)` or relative only); photos fall back to a neutral placeholder if they fail.

The content written into the HTML files is only the fallback. The sheet is the source of truth.

## Running it locally

```bash
python3 -m http.server 5173                       # serve the site at http://localhost:5173
python3 tools/mock-api.py                         # a pretend Apps Script at http://localhost:5174
# open  http://localhost:5173/?api=http://localhost:5174/
```

The `?api=` address is only honoured when the site is opened from `localhost`. Edit `data/sample-content.json` and reload to see content changes. Set `MOCK_DATA=/path/to/other.json` to serve a different file. `MOCK_DELAY=2` slows responses to imitate Google.

Test the script (no Google account needed):

```bash
node tools/test-script.js
```

## What is in the sheet

Defined at the top of `apps-script/Code.gs` (`TABS` and `SETTINGS_SPEC`). Each tab has columns with a type (text, image, url, status, order, show...). The script finds columns by header text, so editors can reorder columns safely. Rows are shown when the required column is filled and Show is not unticked, and are sorted by Order. Google Drive links are turned into `https://lh3.googleusercontent.com/d/<id>`; the website adds `=w<width>` to resize.

## Adding or changing an editable area

1. Add a tab spec to `TABS` in `Code.gs` (and example rows in `SAMPLE`).
2. Add a renderer in `content-render.js` (`R.yourKey = function (data) {...}`) and `data-tcs` on the element it fills.
3. Run `node tools/test-script.js --write-sample`, test locally with the mock API, paste the new `Code.gs` into the Apps Script editor and **deploy a new version**.
4. Existing sheets keep working. To get the new tab, create it by hand or run *Set up sheets* again (it only creates missing tabs).

## Notes

- **Caching:** GitHub Pages serves files with about 10 minutes of cache. Scripts and styles are referenced as `file?v=NUMBER`; change the number in each page when you change a code file.
- **Public data:** the web app address is readable by anyone. Keep personal data out of the sheet.
- **Contact form spam:** a hidden field (`company`), a message length limit, and per-hour limits per email address and in total (see `CONFIG` in `Code.gs`).
- **No-JavaScript visitors** see the built-in content from the HTML, but not sheet changes.
- **Accessibility:** tabs use `role="tab"`; form messages use `role="status"`; images from the sheet have empty alt text because each is next to its own name or caption.
